# Серверные проверки

Тесты отправляют настоящие HTTP-запросы к запущенному локальному проекту выбранной ветки, обходя ограничения HTML. Использовать отдельную проверочную БД со справочниками своего варианта и созданным администратором adminpm05. Тест создаёт вымышленных клиентов с уникальными логинами и заявку; прежние данные не удаляет.

Сначала выполнить выбранную инструкцию Flask или PHP и реализовать своё правило. Если тест individual rule падает, проверить имена и значения domain.json и условие до INSERT. Не исправлять тест, чтобы скрыть ошибку сервера. Для собственной граничной проверки добавить отдельный случай и обосновать ожидание.

Распаковать tests.zip. В PowerShell из папки tests выполнить:

```powershell
py -3 -m venv .venv-tests
.\.venv-tests\Scripts\python.exe -m pip install -r requirements.txt
```

Для Flask:

```powershell
.\.venv-tests\Scripts\python.exe http_checks.py --base http://127.0.0.1:5057 --branch flask --case C:\Practice\service-v01\case.json --admin adminpm05
```

Для PHP вместо предыдущей команды:

```powershell
.\.venv-tests\Scripts\python.exe http_checks.py --base http://127.0.0.1:8057 --branch php --case C:\Practice\service-v01\case.json --admin adminpm05
```

Путь к case.json заменить настоящим путём собственного варианта. При пробелах заключить его в двойные кавычки. Ввести вымышленный пароль своего проверочного администратора по запросу; ввод скрыт. Реальные пароли не использовать. Сервер оставить работающим в другом окне. Ожидается 36 строк PASS и итог «36 checks passed». results.json записывает фактические результаты; при FAIL журнал сохраняет уже выполненные случаи. Повторять тест после исправления, сохраняя предыдущий журнал под другим именем.

Проверяются шесть отказов регистрации (включая ФИО из пробелов), корректная регистрация, дубликат логина, CSRF, неверный пароль, вход клиента, регистрация/вход второго клиента, вход администратора, индивидуальное правило, пять ошибок заявки (включая превышение длины), создание/получение id/начальный статус, чужая карточка, запрет клиентского статуса, ранний отзыв, пропуск статуса, недействующий исполнитель, начало работы, пустой результат, завершение, чужой/короткий/правильный/повторный отзыв и выход.

Дополнительно вручную сравнить SQL-числа строк до и после каждого отказа; проверить фильтры, историю из трёх событий, границы числовых полей, все значения выбора, сохранение полей при ошибке и чистый повтор. HTTP-проверки не заменяют GUI-проход и собственные доказательства.
