# Сервисный центр учебной техники · ПМ.05

Пример серверной части производственной практики ПП.05.01 для РВМП, 7 семестр. Выберите Flask либо PHP и сразу создавайте свой проект по методическим рекомендациям. Код примера служит основой: свою конфигурацию, предметное правило, объяснение и соседний тест нужно разработать для выбранной области.

В общем архиве корень `demo/`: schema.sql и domain.json находятся рядом с папками flask и php. В отдельных flask.zip и php.zip находится только выбранная ветка и общие файлы. Все начальные записи вымышлены.

## Общая подготовка

Нужен установленный MySQL/MariaDB и DBeaver. Создайте отдельную БД pm05_flask или pm05_php с utf8mb4. В новой пустой БД выполните schema.sql своего набора vNN. Шесть таблиц: users, services, technicians, tickets, ticket_history и ticket_reviews. Пользователей создаёт приложение. Две ветки используют отдельные БД, потому что форматы хешей паролей различаются.

Конфигурация через переменные окружения: DB_HOST (по умолчанию 127.0.0.1), DB_PORT (3306), DB_NAME (pm05_flask либо pm05_php), DB_USER (root), DB_PASSWORD (пустая строка). Значения своего учебного сервера задайте перед запуском в том же терминале. Не публикуйте реальные реквизиты. Учебный сервер слушает только локальный адрес.

## Flask в Windows / PowerShell

Из папки flask:

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
$env:DB_HOST="127.0.0.1"
$env:DB_PORT="3306"
$env:DB_NAME="pm05_flask"
$env:DB_USER="root"
$env:DB_PASSWORD=""
.\.venv\Scripts\python.exe -m flask --app app create-admin
.\.venv\Scripts\python.exe -m flask --app app run --port 5057
```

create-admin выполняют один раз на новой БД; введите adminpm05 и вымышленный учебный пароль. Откройте http://127.0.0.1:5057/register. После изменения кода остановите сервер Ctrl+C и запустите вновь. Если APP_SECRET не задан, приложение создаёт секрет на запуск и прежние сессии после перезапуска становятся недействительными.

## Flask в macOS/Linux

Из папки flask:

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
DB_NAME=pm05_flask DB_PORT=3306 .venv/bin/python -m flask --app app create-admin
DB_NAME=pm05_flask DB_PORT=3306 .venv/bin/python -m flask --app app run --port 5057
```

При необходимости добавьте DB_HOST, DB_USER и DB_PASSWORD перед командой. Для учебной среды без интернета преподаватель заранее предоставляет установочные пакеты. Python проверен с Flask 3.1.3 и PyMySQL 1.2.0.

## PHP в Windows / PowerShell

В XAMPP запустите MySQL. Нужны PHP 8.2+, pdo_mysql, mbstring, JSON. Из папки php:

```powershell
$env:DB_HOST="127.0.0.1"
$env:DB_PORT="3306"
$env:DB_NAME="pm05_php"
$env:DB_USER="root"
$env:DB_PASSWORD=""
C:\xampp\php\php.exe create-admin.php
C:\xampp\php\php.exe -S 127.0.0.1:8057
```

В macOS/Linux используйте установленную команду php и префикс DB_NAME=pm05_php DB_PORT=3306 перед каждой командой. create-admin.php принимает учебный логин и пароль из STDIN; пароль отображается, поэтому вводите только вымышленный пароль. Из браузера скрипт недоступен. Откройте http://127.0.0.1:8057/index.php?page=register. Этот воспроизводимый запуск использует PHP и MySQL из установленной среды; для Apache конфигурацию окружения задают отдельно. Встроенные серверы Flask/PHP предназначены для локальной разработки.

## Проверка

Зарегистрируйте вымышленного клиента: client01, Учебный Клиент, 8(999)123-45-67, client@example.test. Пароль — не менее 8 символов и не более 64 байт UTF-8. Создайте заявку EDU-105 на диагностику питания. При отсутствии ответа о блоке питания ожидается отказ; «Да» и «Нет» допустимы. Войдите администратором, назначьте мастера, примите в работу, завершите с описанием результата. История должна содержать создание и два перехода.

Второй клиент не видит первую заявку; чужая карточка возвращает 404, клиентский запрос изменения статуса — 403. Повторный логин, неизвестная услуга, подменённое значение списка и отсутствующий токен формы отклоняются. Неудачная операция не добавляет заявку или событие истории.

## Индивидуальная область

Используйте свой набор vNN: schema.sql, domain.json, case.json и README.md. fields поддерживает text, select с choices, number/integer с min/max, required и pattern. rules поддерживает when + require либо when + expect. В индивидуальных наборах rules оставлен пустым для самостоятельной реализации. Существенные сущности и регулярно используемые поля отражайте в типизированной схеме БД.
